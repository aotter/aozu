# AOZU 產品計劃

狀態：提案基線（2026-08-31）

## 1. 產品命題

一般 AI 助理完成一次工作後，對話、能力與成果很容易散落。一般虛擬寵物雖然有情感連結，卻很少真正參與使用者的生活。AOZU 把兩者結合：

> 使用者帶著同一個角色完成真實世界任務；任務成果會成為角色的成長、外觀、共同記憶與可重複使用的能力。

角色不是裝飾在工具外面的聊天視窗，而是任務的共同參與者。每一個面向都落在同一個循環：

```text
提出生活目標 → 角色共同規劃 → 使用者確認 → 一起執行
→ 留下作品與記憶 → 規則驗證完成 → 點數／外觀／能力成長
→ 將成熟能力封裝成卡片 → 下次再次召喚
```

## 2. 共用產品骨架

AOZU 不為每一種用途重做一個 App。所有用途都由七種共用物件組成：

| 物件 | 說明 |
| --- | --- |
| Companion | 身分、個性、外觀、關係與可使用能力的角色 |
| Quest | 有目標、步驟、證據、完成條件與獎勵的任務 |
| Life Record | 步數摘要、訓練、飲食與帳務等有型別、可更正的生活紀錄 |
| Artifact | 共同產出的旅行書、行程、筆記、章節、課表或訓練紀錄 |
| Memory | 經使用者確認、分級且可刪除的共同記憶摘要 |
| Item | 服裝、配件、場景與具有功能的裝備 |
| Ability Card | 封裝特定能力、必要記憶摘要及來源的可召喚卡片 |

### 進度迴圈

參考 Companion 的 Mantle／Playbook 設計，AOZU 用少量迴圈組合多種服務：

| 用途 | 主要迴圈 | 代表成果 |
| --- | --- | --- |
| 計步 | 節奏＋挑戰 | 每日步數、連續紀錄、散步任務與旅行里程 |
| 健身教練 | 節奏＋精通＋挑戰 | 訓練計劃、動作教材、訓練與恢復紀錄 |
| 飲食管理（飲控） | 節奏＋照護＋精通 | 餐食紀錄、習慣目標、採買／備餐清單 |
| 個人記帳 | 節奏＋照護＋精通 | 收支帳、預算、現金流摘要與旅行旅費 |
| 虛擬人物／戀愛互動 | 羈絆＋旅程 | 關係階段、共同事件、私密記憶 |
| 旅行 | 探索＋旅程＋挑戰 | 有來源的旅行書、可執行行程、旅後紀錄 |
| 共寫筆記／小說 | 精通＋旅程 | 版本化筆記、人物設定、章節與決策 |
| 語言學習 | 節奏＋精通＋羈絆 | 每日練習、錯題記憶、情境對話 |

不同用途可以共存。Today 顯示步數、今日訓練、餐食與當日支出的短摘要，但一次只突出一個當前 Quest，避免把角色變成塞滿入口的儀表板。

## 3. 成長、點數與獎勵

AOZU 沿用 AotterPassport 的八大維度語言：探索、品味、專注、智識、活力、社交、豪氣、幸運。任務只能透過固定規則把可驗證事件轉為維度經驗，不讓模型直接寫入總分。

初版保留四個最小狀態：

1. **八大維度**：跨任務的長期成長。
2. **AOZU Points**：任務獎勵餘額；只用於 AOZU 內解鎖，不可兌現或轉出。
3. **Bond**：使用者與單一角色的羈絆；來自共同完成與主動確認的記憶。
4. **Energy**：角色的日常狀態；可以被步數、休息與互動恢復，不用羞辱或高壓懲罰逼迫回訪。

獎勵順序固定為：完成條件驗證 → 使用者確認 → 寫入不可重複的完成事件 → 發點與經驗 → 判斷解鎖。AI 只能提出候選獎勵說明，無權改餘額、稀有度或完成狀態。

Points 獎勵的是「完成已同意、可安全執行的行動」與「維持紀錄」，不是數字越極端越好：不因少吃更多、運動更久或花更多錢而加倍發點。手動紀錄與裝置摘要都可完成任務，來源只影響可信度標記，不製造羞辱式的真假玩家分級。

### 外觀與能力成長

- 探索提高：旅行裝備、地圖、相機與新場景。
- 品味提高：服裝材質、配色與房間裝飾。
- 專注／智識提高：筆記、平板、研究與教學配件。
- 活力提高：運動服、步行與訓練動作。
- 社交／羈絆提高：新對話、表情與共同合照場景。

外觀道具與功能權限分開。穿上「相機」不代表網站自動取得相機權限；具備功能的道具必須另有明確能力與授權。

## 4. 能力卡

當某項能力達到里程碑，AOZU 產生一張可收藏、裝備與再次召喚的 Ability Card。卡片是經驗的可攜入口，不是完整瀏覽紀錄的副本。

每張卡至少包含：

- 卡名、角色、能力等級與版本。
- 能做的事，以及不能做的事。
- 需要使用者授權的工具範圍。
- 經使用者確認的偏好／記憶摘要引用。
- 產生它的任務與作品來源。
- 視覺外觀、裝備與場景快照。
- 更新日期、相容版本與撤銷狀態。

例：「布丁獺・三日城市旅行規劃 Lv.1」可以重新建立旅行需求、比較有來源的景點與整理日程；它記得使用者偏好步行、咖啡店與不要排太早，但不保存登入憑證、付款資料或整份瀏覽歷史。

能力卡初版由里程碑必定取得，不採隨機抽卡。未來若加入卡池，必須和任務能力卡分流，並另外處理機率揭露、未成年與付費規範。

## 5. 首發生活版

首發版不是五個彼此分離的小工具，而是一位角色陪伴的一天：早上看今日步數與散步任務，依身體狀態調整訓練，餐後留下簡短餐食紀錄，消費後整理帳目，準備旅行時把可用預算、步行能力與飲食偏好帶入行程。每個模組都能單獨關閉，關閉後角色不得再讀它的摘要。

### 計步

- 顯示日／週步數、目標、連續紀錄與旅行累積里程。
- 先支援人工輸入與 CSV；裝置整合只讀每日步數摘要，不要求背景路線。
- 重複匯入以日期、來源與外部識別碼去重；更正以新 revision 留痕。
- 角色可提議散步 Quest，但使用者可依天氣、疼痛與安全狀況跳過，不扣 Bond 或威脅失去角色。

### 健身

- 記錄運動種類、時間、組次／重量（適用時）、自覺強度與完成感受。
- 角色先提供一般性的訓練安排、動作提醒、漸進與休息；疼痛、傷病、懷孕、慢性病或復健需求導向專業人員。
- 任務依計劃完成和安全回顧發獎，不鼓勵超量加練；使用者可調低目標而不被懲罰。
- 訓練能力卡保存確認過的偏好、可用器材與週期摘要，不保存完整健康紀錄。

### 飲食管理（飲控）

- 支援文字、常用餐、照片候選與採買清單；照片辨識只能產生待確認項目。
- 核心是規律、均衡、補水、備餐與使用者自訂習慣。熱量與體重追蹤是可選功能，不預設開啟。
- 過敏、宗教／文化、預算與就醫需求分開標示；角色不做疾病飲食處方或宣稱治療效果。
- 不使用「吃壞了」「作弊餐」等羞辱語言，不以低攝取量、體重下降或連續節食發放更多 Points。
- 飲食能力卡只保存使用者確認的偏好、禁忌與可接受摘要；原始餐食照片預設不進長期記憶。

### 個人記帳

- 支援手動收支、常用項目、收據／CSV 候選、帳戶、分類、預算與月度現金流。
- 金額以幣別最小單位整數保存；轉帳成對標記，不重複計入收入／支出；更正不覆蓋稽核歷史。
- OCR 或 Agent 只能提出商家、金額、日期與分類候選，使用者確認後才入帳。
- 角色可以提醒預算、整理旅行旅費與回顧趨勢，不提供投資、借貸、報稅或保證獲利建議。
- 記帳 Points 獎勵完成紀錄、對帳與自訂預算回顧，不按消費金額發獎。
- 記帳能力卡保存分類規則與預算偏好摘要，不保存完整逐筆帳、銀行憑證或卡號。

## 6. 跨模組旅行故事

### 使用者故事

> 我想和布丁獺安排三天兩夜的城市旅行。角色陪我查看多個旅遊網站，將可追溯的資訊整理成旅行書，提出每日行程。我確認後把行程帶著走，完成旅程時角色獲得探險服、點數與旅行規劃能力卡。下次我可直接召喚這張卡，沿用我確認過的偏好規劃另一個城市。

### 體驗步驟

1. 選角色、目的地、日期、預算、同行者、步行能力與偏好。
2. Agent 瀏覽網站；AOZU 只接收有 URL、擷取時間與摘要的候選資料。
3. 角色把資料編成旅行書，標出衝突、過期風險與未確認事項。
4. 使用者確認景點與節奏，系統排出可編輯行程。
5. 使用者逐項選擇是否帶入步行能力、飲食偏好和旅行預算摘要；未授權模組維持不可見。
6. 旅途中以人工勾選開始；之後才接日曆、定位、訂票或步數權限，旅費由記帳模組另行確認入帳。
7. 每日回顧產生共同日誌，是否成為長期記憶由使用者決定。
8. 行程完成後由規則發放 Points、探索／活力經驗與探險配件。
9. 達成里程碑時建立旅行能力卡；再次使用時先顯示將帶入的記憶摘要。

### 完成定義

只有「看過網站」不能算完成。首發版需同時具備：旅行書已由使用者接受、至少一日行程被標記執行、旅後回顧已確認。完成條件日後可由訂位、日曆或定位證據加強，但不可在沒有授權時偷偷追蹤。

## 7. 其他情境的最小形狀

### 戀愛／交友

- 初版是使用者和虛擬角色的私人關係敘事，不做真人配對。
- 角色不得要求排他、以離開／生病威脅使用者，或把付費與感情承諾綁定。
- 親密內容、年齡門檻、危機處理與記憶刪除完成安全設計後才開放更深層互動。

### 共筆／小說

- Artifact 具備版本、作者來源與可回復歷史，角色提案不會直接覆寫使用者文字。
- 記憶只保存使用者選定的設定與摘要，原稿仍是獨立作品。

### 語言學習

- 角色依程度和興趣建立短練習，記住由使用者確認的常錯項目。
- 能力成長依完成與複習結果，不依模型對語言程度的主觀猜測。

## 7. 核心原則

- **先有實用成果，再有遊戲獎勵。** 獎勵放大完成感，不取代任務價值。
- **共同記憶必須可見、可編輯、可忘記。** 對話歷史不自動等於長期記憶。
- **角色人格不等於系統權限。** 再親密的角色也不能繞過確認、付款或資料權限。
- **作品可攜。** 使用者可匯出角色、作品、卡片與素材；不能把離開成本當留存機制。
- **敏感領域分艙。** 健康、飲食與帳務各自授權；跨模組只分享使用者在當下預覽並確認的摘要。
- **來源可追溯。** 旅行、學習與研究內容保留來源、擷取時間及不確定性。
- **沒有 Agent 仍可使用。** 角色檢視、衣櫥、任務、作品與匯出不以 WebMCP 是否存在為啟動門檻。
